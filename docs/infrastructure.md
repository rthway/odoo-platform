## Reaching the monitoring stack

Grafana, Prometheus and Alertmanager bind to `127.0.0.1`. None has
authentication strong enough to face the internet.

```bash
ssh -L 3000:127.0.0.1:3000 \
    -L 9090:127.0.0.1:9090 \
    -L 9093:127.0.0.1:9093 \
    <user>@157.10.100.232
```

Then <http://localhost:3000>.

## Firewall

`roles/common` applies ufw with default-deny inbound and allow outbound.

**The SSH allow rule is added before the default-deny policy is set.** The
reverse order locks everyone out of a remote host with no console, which
requires provider intervention to undo. Do not reorder those tasks.

## Capacity

Suggested minimums, pending the audit:

| | DEV | QA | PROD | OPS |
|---|---|---|---|---|
| vCPU | 2 | 4 | 4+ | 4 |
| RAM | 4 GB | 8 GB | 16 GB | 8 GB |
| Disk | 40 GB | 80 GB | 200 GB+ | 200 GB+ |

`ODOO_WORKERS` should be `(2 × vCPU) + 1`. Confirm `nproc` on the host before
setting it — the value in `.env.prod.example` is a placeholder, not a
measurement.

PROD disk must accommodate the database, the filestore, WAL archive and
Docker images. OPS must hold the full retention set: 14 daily + 8 weekly +
12 monthly.

## DNS and TLS

No domain is currently configured. The intended layout:

| Name | Points to |
|---|---|
| `odoo.example.com` | PROD .231 |
| `odoo-qa.example.com` | QA .230 |
| `odoo-dev.example.com` | DEV .223 |
| `grafana.example.com` | OPS .232 (behind VPN) |

Until real names exist, DEV and QA run self-signed certificates generated by
`roles/odoo_deploy`. **Production refuses to configure without a real
certificate** — that assertion is deliberate.
